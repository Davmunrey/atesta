# Spec: Multi-tenant data layer

- Requirement ids: NFR-02, NFR-03, FR-13, MF-01
- Status: draft
- ADRs: ADR-008, ADR-012 (proposed)
- Build order: 1 of 3 (identity and control-model specs depend on it)

## Problem

Every Atesta table holds data of many customer organizations. One query that forgets
`WHERE organization_id = ...` leaks one customer's security posture to another: a fatal incident
for a compliance vendor. Isolation must not depend on every query being written correctly.

## Acceptance criteria

- [ ] SQLAlchemy 2 (sync, typed `Mapped[]`) and Alembic, one migration history for the monolith
      in `apps/api/migrations/`.
- [ ] Postgres 16. Two roles: `atesta_owner` owns the schema and runs migrations; `atesta_app` is
      the only runtime role: not owner, not superuser, `NOBYPASSRLS`.
- [ ] Every tenant table has `organization_id uuid NOT NULL` (FK to `organizations(id)`,
      `ON DELETE RESTRICT`), an index leading with `organization_id`, RLS enabled and the standard
      `tenant_isolation` policy below.
- [ ] Global tables are a closed allowlist (ADR-012): `users` (own policy, identity spec), catalog
      tables (SELECT only for `atesta_app`, control-model spec), `alembic_version`.
- [ ] Tenant context is set per transaction only (`set_config(name, value, true)`), never per
      session. No context means zero rows: never an error, never all rows.
- [ ] API startup fails if the runtime role owns any table, is superuser or has BYPASSRLS.
- [ ] `audit_events` table plus `platform.audit.record()` writing in the caller's transaction;
      `atesta_app` has INSERT and SELECT only (append-only by grant).
- [ ] CI runs DB tests against a Postgres 16 service container pinned by digest. DB tests are
      mandatory in CI and skipped locally only when no test database URL is set.

## Out of scope

- RDS provisioning and DB credentials in Secrets Manager (infra spec).
- pgvector (AI spec), Procrastinate schema (scanning spec).
- Read replicas, partitioning, PgBouncer.
- Org offboarding and data deletion job (NFR-08, offboarding spec).

## Design notes

### Layout

```text
apps/api/src/atesta_api/
  platform/              Shared kernel, not a module. Imports no module (import-linter layers).
    db.py                Engine, sessionmaker, Base with naming convention, TenantMixin
    tenancy.py           TenantContext, set_tenant_context()
    rls.py               SQL helpers for migrations: enable RLS + standard policy + grants
    audit.py             record()
  modules/<m>/models.py  ORM models, private to the module
apps/api/migrations/     Alembic env + versions; env.py imports every module's models
```

Modules may import `platform`; `platform` imports no module. ADR-008 module list is unchanged.

### Tenant context

Transaction-local settings, set by `set_tenant_context(session, ctx)` right after BEGIN:

| Setting | Value | Read by |
|---|---|---|
| `app.subject` | Cognito `sub` from a verified token | `users` policy (self lookup) |
| `app.user_id` | `users.id` of the caller | `memberships` policy (own orgs) |
| `app.organization_id` | Active org, set after a membership check | Every tenant table |

The identity spec adds one more (`app.invitation_token_sha256`) for invitation acceptance.

Standard policy, generated by `platform.rls` and applied in migrations:

```sql
ALTER TABLE t ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON t
  USING (organization_id = NULLIF(current_setting('app.organization_id', true), '')::uuid)
  WITH CHECK (organization_id = NULLIF(current_setting('app.organization_id', true), '')::uuid);
```

- `NULLIF(..., '')`: once a transaction that used `set_config(..., true)` ends, Postgres resets
  the custom setting to `''`, not NULL, and `''::uuid` raises. NULL compares false, so no context
  returns no rows.
- Pool safety: transaction-local settings die with the transaction, so a pooled connection never
  carries the previous tenant. Session-level `SET app.*` is forbidden (test greps for it).

### What RLS does and does not do

RLS stops a query that forgets the tenant filter. It does not stop app code that sets the wrong
context. The context is set in one place only: `identity.api`, after a membership check or a valid
invitation acceptance. Role checks stay in the app (`identity.api.require_role`).

### Conventions

| Topic | Rule |
|---|---|
| Primary keys | Tenant tables: `id uuid`, uuid4 generated in Python. Catalog tables: natural text keys (control-model spec). |
| Timestamps | `created_at timestamptz NOT NULL DEFAULT now()`; `updated_at` only where rows change. |
| Enumerations | `text` + CHECK constraint, not Postgres ENUM (cheap to extend). |
| Constraint names | Naming convention on `MetaData`, so Alembic autogenerate diffs are stable. |
| Cross-module FKs | Only to `organizations.id` (tenant root). Other cross-module references are plain columns validated through the owning module's `api.py` (ADR-008: no cross-module joins). |
| Deletes | `ON DELETE RESTRICT` to `organizations`. Offboarding asks each module through its `api.py`. |

### Drivers, sync vs async, licenses

| Choice | Decision | Why |
|---|---|---|
| Driver | psycopg 3 | Procrastinate (ADR-003) requires it; one driver for both. |
| License | psycopg is LGPL-3.0 | Used unmodified as a library. ADR-006 amendment proposed: LGPL libraries allowed, AGPL/GPL stay banned. |
| ORM / migrations | SQLAlchemy 2, Alembic | MIT. |
| Sync vs async | Sync | One builder, low load, simpler tests; FastAPI runs sync endpoints in a threadpool. Revisit on ADR-008 triggers. |

### Audit events

`audit_events(id, organization_id, actor_user_id NULL, action, target_type, target_id, metadata
jsonb, request_id, occurred_at)`.

- `action` is a dotted code, e.g. `org.created`.
- `record()` takes typed scalar fields only, no free-form blobs, so secrets, tokens and document
  contents cannot reach `metadata` (CLAUDE.md rule 2).
- Grants: `atesta_app` INSERT, SELECT. No UPDATE, no DELETE.
- Events always belong to an org. User-level events without an org (sign-up, login) stay in
  Cognito and CloudTrail.

## Test plan

| Test | Proves |
|---|---|
| Schema linter: every table in `public` outside the allowlist has `organization_id NOT NULL`, RLS enabled, the `tenant_isolation` policy and an index leading with `organization_id` | Rule 3 holds for every future table, automatically |
| Cross-tenant matrix on a probe table, orgs A and B: context A sees only A; insert with B's id fails WITH CHECK; update and delete of B's rows affect 0 rows | RLS isolation |
| No context: SELECT returns 0 rows. Same pooled connection after a tenant transaction: 0 rows | Fail closed, no leak across the pool |
| Runtime role: `atesta_app` not owner, not superuser, no BYPASSRLS; startup guard raises when misconfigured | Defense in depth |
| `audit_events`: UPDATE and DELETE as `atesta_app` raise permission denied | Append-only |
| Alembic: upgrade head from empty DB, downgrade base, upgrade head again | Migrations reversible |

DB fixture: creates both roles, migrates as `atesta_owner`, runs tests as `atesta_app`, rolls
back each test's transaction.
